# SEO, crawlability, accessibility & performance audit

Run: 2026-10-29 · Lighthouse 12 (mobile, simulated throttling) · axe-core 4 via Playwright (reduced motion, 1280px + 390px)

| Category       | Live site before | After (local preview of `dist`) |
|----------------|------------------|---------------------------------|
| Performance    | 90               | 97                              |
| Accessibility  | 81               | 100                             |
| Best practices | 100              | 100                             |
| SEO            | 91               | 100                             |
| axe violations | —                | 0 (desktop + mobile)            |

The biggest problem was not visible in Lighthouse: the site shipped an empty `<div id="root">`,
so crawlers that don't run JavaScript (GPTBot, ClaudeBot, PerplexityBot, social link previews)
saw no content at all, and Google only saw it after JS and the GraphQL call both succeeded.

## Crawlability (search engines + AI search)

- [x] **Build-time prerender.** `npm run build` now also builds `src/entry-server.tsx` for SSR and
  runs `scripts/prerender.mjs`, which fetches the WordPress content (same `getHomePageData`
  service), renders the page to HTML and writes it into `dist/index.html`. The build fails if
  WordPress is unreachable, so an empty page is never deployed.
- [x] Browser hydrates the prerendered HTML (`hydrateRoot`) and seeds React Query from the
  embedded `<script id="__HOME_DATA__">`, then refreshes in the background.
- [x] Static sections (About, Contact, form, header, footer) are no longer hidden behind the
  full-screen spinner while WordPress loads.
- [x] `robots.txt` allows all crawlers, with explicit entries for search and AI bots, plus `Sitemap:`.
- [x] `sitemap.xml` generated at build (homepage + OG image + product images, `lastmod` = build date).
- [x] `llms.txt` generated at build: brand summary, products with ingredients, services, links.
- [x] `netlify.toml`: build command, immutable cache headers for `/assets/*`.
- [ ] **Netlify setup (manual):** set `VITE_WP_DOMAIN=https://api.boissonsolutionx.ca` and
  `VITE_SITE_URL=https://boissonsolutionx.ca` in Site configuration › Environment variables.
- [ ] **Rebuild on content change (manual):** create a Netlify Build hook and call it from
  WordPress on publish/update, otherwise crawlers keep the content from the last deploy.
- [ ] Submit `https://boissonsolutionx.ca/sitemap.xml` in Google Search Console and Bing Webmaster Tools.

## Accessibility

- [x] Visible `:focus-visible` outline everywhere (form inputs had `outline: none`).
- [x] `<main id="main">` landmark + "Aller au contenu" skip link.
- [x] `scroll-margin-top` so anchored sections aren't hidden under the fixed header.
- [x] Mobile menu: accessible name, `aria-expanded`, `aria-controls`, `<nav>`, closes on Escape.
- [x] Form: `required`, `autocomplete`, `aria-invalid`, `aria-describedby` → error text,
  `aria-live` status for the submit result, `onSubmit` on the form. Error messages in French.
- [x] CTA "buttons" are real links (`#ourProducts`, `#contactForm`) instead of JS `navigate()`
  calls; `Button asLink` no longer nests `<button>` inside `<a>`.
- [x] Contrast: red CTA `red-500` → `red-600` (white text 3.8:1 → 4.8:1), footer `gray-500` →
  `gray-400`, nav hover `gray-500/75` → brand `secondary`.
- [x] Decorative icons/blobs `aria-hidden`; descriptive alt texts; `prefers-reduced-motion` respected.
- [x] Footer external link `rel="noopener noreferrer"`; "Accueil" typo; French footer text.

## Performance

- [x] LCP background `bottles.webp` preloaded with `fetchpriority="high"`.
- [x] `about.png` (441 KB) → `about.webp` (31 KB), lazy-loaded with dimensions.
- [x] Product images: `width`/`height` from WPGraphQL `mediaDetails`, `loading="lazy"`,

# Re-audit after the "Dark cinematic" redesign

Run: 2026-10-29 · Lighthouse 12 (3 mobile runs + desktop) · axe-core 4.14 (desktop 1280px + mobile 390px,
reduced motion) · pixel-sampled contrast for text over images and gradients (axe can't measure those).

| Category              | Before re-audit | After           |
|-----------------------|-----------------|-----------------|
| Performance (mobile)  | 92              | 95 (FCP 2.1 → 1.5 s) |
| Performance (desktop) | 100             | 100             |
| Accessibility         | 100             | 100             |
| Best practices        | 100             | 100             |
| SEO                   | 100             | 100             |
| axe violations        | 0               | 0               |
| Worst text contrast   | 3.06:1 (hero eyebrow, mobile) | 4.65:1 (white on brand-red button) |

## Fixed

- **Contrast:** the small coral hero eyebrow sat on the orange bottle on phones (3.06:1). Stronger
  mobile scrim at 60 % (`via-ink/90`). The clear header over the hero could put the coral active
  link on a juice splash; a top scrim (`from-ink/85`) now sits behind the header.
- **Form accessibility:** field errors were inside the `<label>`, so the error became part of the
  field's name ("Nom Complet * Nom complet requis") and was read twice. The error is now outside
  the label and only linked with `aria-describedby`.
- **Error screen on a WordPress outage:** a failed background refresh flipped React Query to
  `error` after ~7 s and replaced the prerendered hero and products with "Erreur de chargement".
  `useHomePageData` now reports an error only when there is no content to show.
- **Responsive product images:** the query now asks WPGraphQL for `srcSet` (300/768/1024 px) and
  the cards set `sizes`, so phones stop downloading the 1024 px originals (~240 KB saved).
- **Faster first paint:** the build preloads the above-the-fold fonts (Inter + Playfair latin) and
  preconnects to the WordPress host.
- **Social / head metadata:** `og:image:type`, `twitter:image:alt`, and a 180×180 PNG
  `apple-touch-icon` (iOS ignores the old wide WebP logo).
- **Netlify headers:** week-long cache for root images, `X-Content-Type-Options`, `Referrer-Policy`.
- **Backend (`functions.php`):** `createContactMessage` called `wp_insert_post()` without
  `$wp_error = true`, so a failed save returned `0` and was reported to the visitor as a success.
  `createSubmission` returned a PHP array in a GraphQL `String` field (since removed, below).
- **Removed `createSubmission`** (ACF `form_submission` mutation): the site never called it (only
  `createContactMessage`, since the first form version), it sent no email, and it accepted
  anonymous writes with no honeypot or rate limit. Saving and emailing contact messages is
  unchanged. Takes effect once `functions.php` is uploaded to the WordPress theme; old
  `form_submission` posts stay in WP admin.

## Still open (outside this repo)

- **WordPress uploads have no cache headers** (`Cache-Control` missing on `/wp-content/uploads/*`,
  ~370 KB re-downloaded on every visit). Add an expiry rule on the WordPress host (`.htaccess`
  `mod_expires`, or the host's cache settings).
- **Content in WordPress:** the h1 is still "Solution X"; Betterave says "céléry"; the Watermelon
  ingredients are a copy of Hibiscus.
- **Product JSON-LD** has no `offers` (no prices on the site), so Google won't show product rich
  results; the data still helps AI answers. Add prices in WordPress to enable them.
- Remaining mobile LCP (~2.9 s, simulated slow 4G) is the hero paragraph waiting for CSS and
  fonts; the next step would be inlining critical CSS.

| `npm test` (77 tests, 99 % lines) | Vitest + Testing Library (jsdom) | components, hooks, contact form flow, GraphQL service, SSR prerender output, axe structure check |

`.github/workflows/ci.yml` runs three jobs on every push to `main` and every PR: frontend
(lint, types, unit + coverage), e2e (build with live WordPress, Playwright, Lighthouse), and
backend (PHP 8.3 syntax check + PHPUnit).
